# Forgejo Connector для VS Code

Інтеграція Forgejo (і сумісної Gitea) з вбудованим Git у VS Code — так само, як це зроблено для GitHub.

## Можливості

- **Git: Clone → Clone from Forgejo** — список ваших репозиторіїв і репозиторіїв ваших організацій з пошуком
  (пошук також знаходить публічні репозиторії інших користувачів на сервері).
- **Publish to Forgejo** у порожній панелі Source Control (папка ще без git) — як «Publish to GitHub»:
  назва й видимість → вибір файлів (якщо немає `.gitignore`) → створення репозиторію, `git init`,
  перший коміт і push. Також команда **Forgejo: Опублікувати у Forgejo**.
- **Publish Branch / Publish to Forgejo** (кнопка в панелі Source Control для проєкту без remote) —
  створює репозиторій у Forgejo, підключає його як `origin` і відправляє поточну гілку.
- **Forgejo: Створити репозиторій** — створення для себе або організації: назва, опис, видимість,
  порожній або з README. Після створення: клонувати, підключити поточний проєкт або відкрити в браузері.
- **Forgejo: Клонувати репозиторій** — те саме, що Git: Clone, але одразу зі списком Forgejo.
- SSH або HTTPS (налаштування `forgejo.cloneProtocol`: `ssh`, `https` або `ask`).
  Для HTTPS розширення саме передає git ваш логін і токен — пароль вводити не потрібно.

## Встановлення

1. Extensions (Cmd/Ctrl+Shift+X) → меню `…` → **Install from VSIX…** → `forgejo-connector-<версія>.vsix`.
   Або з термінала: `code --install-extension forgejo-connector-0.3.3.vsix`.
2. Command Palette (Cmd/Ctrl+Shift+P) → **Forgejo: Увійти**:
   - адреса сервера, наприклад `https://git.example.ua` (зберігається в налаштуванні `forgejo.url`);
   - токен доступу (див. нижче «Токен доступу»).

## Токен доступу

У Forgejo: **Налаштування → Застосунки → Створити новий токен**. Кнопка «Створити токен у браузері»
в діалозі входу одразу відкриває цю сторінку.

| Параметр токена | Значення | Для чого |
|---|---|---|
| Доступ до репозиторіїв і організацій | **Усі** (публічні, приватні та обмежені) | інакше приватних репозиторіїв не буде видно |
| `repository` | **Читання й запис** | список і пошук репозиторіїв, створення, клонування й push через HTTPS |
| `user` | **Читання й запис** | вхід (`/user`); створення особистого репозиторію (`POST /user/repos`) вимагає саме запису в `user` |
| `organization` | **Читання й запис** | список організацій та їхніх репозиторіїв; запис потрібен, щоб створювати репозиторії в організації (інакше досить читання) |
| решта (`issue`, `package`, `notification`, `admin`, …) | Без доступу | не використовуються |

Якщо прав бракує, розширення показує помилку «Недостатньо прав токена». Тоді створіть новий токен
і виконайте **Forgejo: Вийти**, а потім **Forgejo: Увійти**.

Токен зберігається в захищеному сховищі системи (macOS Keychain / Windows Credential Manager),
окремо для кожної адреси сервера. **Forgejo: Вийти** — видалити токен.

Для SSH потрібен SSH-ключ, доданий у Forgejo (Налаштування → SSH / GPG ключі).

## Оновлення

Розширення саме перевіряє останній реліз репозиторію `forgejo.updates.repository` (за замовчуванням
`xDevOps/forgejo-vscode`) — через 15 с після запуску VS Code і далі кожні 6 годин — і, якщо є новіша версія,
пропонує: **Оновити** (завантажує `.vsix` вашим токеном, встановлює й пропонує перезавантажити вікно),
**Що нового** або **Пропустити цю версію**. Перевірити вручну — **Forgejo: Перевірити оновлення розширення**;
вимкнути — `forgejo.updates.check`. Без входу у Forgejo перевірка мовчки пропускається.

### Випуск нової версії

1. Підняти `version` у `package.json`, закомітити.
2. Анотований тег — його повідомлення стане описом релізу й текстом «Що нового»:
   ```
   git tag -a v0.3.1 -m "Що змінилося"
   git push --follow-tags
   ```
3. Forgejo Actions (`.forgejo/workflows/release.yml`, раннер з міткою `forgejo-vscode-ci`, `deploy/runner`, [docs/release.md](docs/release.md)) проганяє тести, збирає `.vsix`
   і створює реліз (`release.py`). Тег має збігатися з версією в `package.json`, інакше реліз не створюється.

## Сервер із внутрішнім сертифікатом

VS Code використовує системне сховище сертифікатів (налаштування `http.systemCertificates`, увімкнене за замовчуванням).
Якщо з'являється помилка «Сертифікат сервера не довірений» — встановіть кореневий сертифікат
у систему (macOS: Keychain Access → System → Always Trust; Windows: certmgr → Trusted Root Certification Authorities)
і перезапустіть VS Code. Для git через HTTPS сертифікат також має бути довіреним для самого git
(`git config --global http.sslCAInfo <шлях до ca.pem>` або `http.sslBackend schannel` на Windows).

## Налаштування

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `forgejo.url` | — | Адреса сервера Forgejo |
| `forgejo.cloneProtocol` | `ssh` | `ssh`, `https` або `ask` (питати щоразу) |
| `forgejo.defaultPrivate` | `true` | Нові репозиторії за замовчуванням приватні |
| `forgejo.updates.check` | `true` | Перевіряти нові версії розширення й пропонувати оновитися |
| `forgejo.updates.repository` | `xDevOps/forgejo-vscode` | Репозиторій, з релізів якого береться оновлення |

## Збірка

Node.js не потрібен — розширення на чистому JavaScript. Пакет `.vsix` збирається скриптом:

```
python3 build_vsix.py
```
